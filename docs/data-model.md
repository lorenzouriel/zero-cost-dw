# Data model

The warehouse lives in the `fruit_juice` database and is defined by the SSDT project in [fruit_juice/](../fruit_juice/).

![ERD](assets/erd.png)

## Schemas

| Schema | Purpose |
|---|---|
| `dim` | Dimension tables |
| `fact` | Fact tables |
| `staging` | Reserved for auxiliary tables; no tables are defined in it yet |

All keys and codes are `NVARCHAR(50)`; descriptions are `NVARCHAR(200)`. Measures are `FLOAT`.

## Dimensions

| Table | Meaning | Key | Notes |
|---|---|---|---|
| `dim.categoria` | Product category (e.g. Juice, Mate, Mineral Water) | `Cod_Categoria` | Top of the product snowflake |
| `dim.marca` | Brand | `Cod_Marca` | FK → `categoria` |
| `dim.produto` | Product | `Cod_Produto` | FK → `marca`; attributes `Atr_Tamanho` (size) and `Atr_Sabor` (flavour) |
| `dim.cliente` | Customer | `Cod_Cliente` | Denormalised geography and segment: city → state → region, plus segment |
| `dim.fabrica` | Factory | `Cod_Fabrica` | Three factories: Rio de Janeiro, São Paulo, Acre (inline in the ETL package) |
| `dim.organizacional` | Sales organisation (managers and reports) | `Cod_Filho` | Parent-child: `Cod_Pai` is a self-referencing FK. `Esquerda`, `Direita`, `Nivel` hold the nested-set positions and depth |
| `dim.tempo` | Calendar day | `Cod_Dia` | One row per day with week, month, quarter, half-year, year and weekday/weekend flag. Generated by script |

### Hierarchies

The attribute hierarchies exposed to users are defined in the SSAS dimensions (see [OLAP](olap.md#dimensions-and-hierarchies)):

- **Product:** Category → Brand → Product (snowflake, three tables)
- **Customer geography:** Region → State → City → Customer
- **Customer segment:** Segment → Customer
- **Organisation:** parent-child via `Cod_Pai`
- **Time, by month:** Half-year → Quarter → Month
- **Time, by month and year:** Half-year-Year → Quarter-Year → Month-Year (codes such as `2014-01`, so members stay unique across years)

## Facts

| Table | Business meaning | Grain (primary key) | Measures |
|---|---|---|---|
| `fact.Fato_001` | **Sales** | customer × product × organisation × factory × day | `Faturamento` (revenue), `Imposto` (tax), `Custo_Variavel` (variable cost), `Quantidade_Vendida` (quantity sold), `Unidades_Vendidas` (units sold) |
| `fact.Fato_002` | **Freight** | customer × product × factory × day | `Frete` (freight cost) |
| `fact.Fato_003` | **Fixed cost** | factory × day | `Custo_Fixo` (fixed cost) |
| `fact.Fato_004` | **Revenue target** | customer × product × organisation × day | `Meta_Faturamento` (revenue target) |
| `fact.Fato_005` | **Cost target** | product × factory × day | `Meta_Custo` (cost target) |

Every dimension key in a fact table is a foreign key to the matching dimension, and the combination of keys is the fact's primary key, so each fact holds **at most one row per grain combination**.

### Dimensional matrix

| | Customer | Product | Organisation | Factory | Time |
|---|:-:|:-:|:-:|:-:|:-:|
| `Fato_001` Sales | ● | ● | ● | ● | ● |
| `Fato_002` Freight | ● | ● | | ● | ● |
| `Fato_003` Fixed cost | | | | ● | ● |
| `Fato_004` Revenue target | ● | ● | ● | | ● |
| `Fato_005` Cost target | | ● | | ● | ● |

Facts can only be compared along the dimensions they share. Freight cannot be split by sales organisation and fixed cost cannot be split by product without allocation — that is the reason for the [complete fact table](olap.md#the-complete-fact-table).

## Stored procedure

`SP_MONTAESQDIR` computes the `Esquerda` / `Direita` / `Nivel` values of `dim.organizacional`. It walks the hierarchy recursively over two scratch tables (`TEMP_AUXTABELA`, `TEMP_AUXCONTROLE`). The driver script that creates those tables and calls the procedure (used by the "Execução da rotina Esq Dir Nivel" task in the dimension package) is in [Sources/Fontes/queries/SP_EXECUTAESQDIR.sql](../Sources/Fontes/queries/SP_EXECUTAESQDIR.sql).

## Source files → dimensions

| Dimension | Loaded from |
|---|---|
| `categoria`, `marca` | `MARCAS E CATEGORIAS.csv` |
| `produto` | `PRODUTOS.xlsx` (brand, flavour and size are parsed out of description columns) |
| `cliente` | `CADASTRO DE CLIENTES.xlsx` + `REGIOES DOS ESTADOS.csv` (city and state parsed from a combined column) |
| `organizacional` | `FUNCIONARIOS GRUPO 1.xlsx`, `FUNCIONARIOS GRUPO 2.xlsx` |
| `fabrica` | Inline query inside the ETL package (three rows) |
| `tempo` | Script [PERIODOS DE TEMPO.sql](../Sources/Fontes/queries/PERIODOS%20DE%20TEMPO.sql) |
